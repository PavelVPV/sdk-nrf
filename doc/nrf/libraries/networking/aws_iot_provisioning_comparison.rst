.. _aws_iot_provisioning_comparison:

AWS IoT provisioning comparison
################################

.. contents::
   :local:
   :depth: 2

This page compares the three device provisioning flows supported for AWS IoT Core, as described in :ref:`generating_and_provisioning_certificates`:

* :ref:`prov_nrf91_csr` — Private key generated **on the nRF91 modem** (most secure; recommended for production).
* :ref:`prov_nrf91_aws_keys` — Key pair generated **by AWS** and injected into the nRF91 modem.
* :ref:`prov_nrf70_aws_keys` — Key pair generated **by AWS** and compiled into the nRF70 firmware (Mbed TLS).

.. _prov_nrf91_csr:

nRF91: Keys generated on device (CSR flow)
******************************************

In this flow, the nRF91 modem generates the key pair internally.
The private key **never leaves the modem**.
Only the Certificate Signing Request (CSR), which contains the public key, is exported.
AWS IoT Core signs the CSR and returns a device certificate, which is then stored in the modem.

.. code-block:: none

   ┌─────────────────────┐          ┌──────────────────┐          ┌──────────────────┐
   │  nRF91 Modem        │          │  Host (PC)       │          │  AWS IoT Core    │
   └──────────┬──────────┘          └────────┬─────────┘          └────────┬─────────┘
              │                              │                              │
              │  1. nrfcredstore generate    │                              │
              │  ──────────────────────────> │                              │
              │     Key pair created in      │                              │
              │     modem (privkey stays)    │                              │
              │  <── device_cert.csr.der ─── │                              │
              │                              │                              │
              │                              │  2. openssl: DER → PEM       │
              │                              │  ──────────────────────────> │
              │                              │                              │
              │                              │  3. aws iot                  │
              │                              │     create-certificate-      │
              │                              │     from-csr                 │
              │                              │  ──────────────────────────> │
              │                              │  <── device_cert.pem ─────── │
              │                              │      (+ certificate ARN)     │
              │                              │                              │
              │  4. nrfcredstore write       │                              │
              │     CLIENT_CERT              │                              │
              │  <────────────────────────── │                              │
              │                              │                              │
              │  5. nrfcredstore write       │                              │
              │     ROOT_CA_CERT             │                              │
              │  <────────────────────────── │                              │
              │                              │                              │
              │  Private key stays on modem throughout the entire flow      │
              │                                                             │

Step summary:

1. Generate key pair and CSR on modem (``nrfcredstore generate``) → exports :file:`device_cert.csr.der`.
#. Convert CSR from DER to PEM format (``openssl req``).
#. Submit CSR to AWS IoT Core (``aws iot create-certificate-from-csr``) → receive signed :file:`device_cert.pem` and certificate ARN.
#. Provision device certificate to modem (``nrfcredstore write … CLIENT_CERT``).
#. Provision Amazon Root CA certificate to modem (``nrfcredstore write … ROOT_CA_CERT``).

.. _prov_nrf91_aws_keys:

nRF91: Keys generated by AWS
*****************************

In this flow, AWS IoT Core generates the key pair and certificate.
The **private key is downloaded to the host** and then injected into the nRF91 modem.
This is less secure than the CSR flow because the private key exists outside the device.

.. caution::
   This option is not recommended for production scenarios because the private key leaves the device.

.. code-block:: none

   ┌─────────────────────┐          ┌──────────────────┐          ┌──────────────────┐
   │  nRF91 Modem        │          │  Host (PC)       │          │  AWS IoT Core    │
   └──────────┬──────────┘          └────────┬─────────┘          └────────┬─────────┘
              │                              │                              │
              │                              │  1. aws iot                  │
              │                              │     create-keys-and-         │
              │                              │     certificate              │
              │                              │  ──────────────────────────> │
              │                              │  <── priv_key.pem ────────── │
              │                              │  <── device_cert.pem ─────── │
              │                              │      (+ certificate ARN)     │
              │                              │                              │
              │  2. nrfcredstore write       │                              │
              │     CLIENT_CERT              │                              │
              │  <────────────────────────── │                              │
              │                              │                              │
              │  3. nrfcredstore write       │                              │
              │     CLIENT_KEY               │                              │
              │  <────────────────────────── │                              │
              │                              │                              │
              │  4. nrfcredstore write       │                              │
              │     ROOT_CA_CERT             │                              │
              │  <────────────────────────── │                              │
              │                              │                              │
              │  Private key was on host before being written to modem      │
              │                                                             │

Step summary:

1. Generate key pair and certificate on AWS (``aws iot create-keys-and-certificate``) → receive :file:`priv_key.pem`, :file:`device_cert.pem`, and certificate ARN.
#. Provision device certificate to modem (``nrfcredstore write … CLIENT_CERT``).
#. Provision private key to modem (``nrfcredstore write … CLIENT_KEY``).
#. Provision Amazon Root CA certificate to modem (``nrfcredstore write … ROOT_CA_CERT``).

.. _prov_nrf70_aws_keys:

nRF70: Keys generated by AWS
*****************************

The nRF70 Series devices use Mbed TLS for the TLS stack instead of a dedicated modem.
Certificates and keys are not stored in dedicated secure hardware; instead, they are loaded into the Mbed TLS stack at runtime from the host file system or embedded directly in the firmware.

There is no modem to generate a key pair or CSR, so only the AWS-generated key flow is supported.
The :ref:`lib_mqtt_helper` library automatically provisions the credentials from the configured certificate folder when connecting.

.. code-block:: none

   ┌─────────────────────┐          ┌──────────────────┐          ┌──────────────────┐
   │  nRF70 Device       │          │  Host (PC)       │          │  AWS IoT Core    │
   │  (Mbed TLS)         │          │  / Build system  │          │                  │
   └──────────┬──────────┘          └────────┬─────────┘          └────────┬─────────┘
              │                              │                              │
              │                              │  1. aws iot                  │
              │                              │     create-keys-and-         │
              │                              │     certificate              │
              │                              │  ──────────────────────────> │
              │                              │  <── private-key.pem ─────── │
              │                              │  <── client-cert.pem ─────── │
              │                              │      (+ certificate ARN)     │
              │                              │                              │
              │                              │  2. Download AmazonRootCA1   │
              │                              │     as ca-cert.pem           │
              │                              │                              │
              │                              │  3. Place PEM files into     │
              │                              │     <app_src>/certs/         │
              │                              │     (CONFIG_MQTT_HELPER_     │
              │                              │      CERTIFICATES_FOLDER)    │
              │                              │                              │
              │  4. At runtime: MQTT helper  │                              │
              │     reads cert files and     │                              │
              │     provisions to Mbed TLS   │                              │
              │  <── certs loaded ────────── │                              │
              │                              │                              │
              │  Device connects using Mbed TLS mutual TLS                  │
              │                                                             │

Step summary:

1. Generate key pair and certificate on AWS (``aws iot create-keys-and-certificate``) → receive :file:`private-key.pem`, :file:`client-cert.pem`, and certificate ARN.
#. Download `Amazon Root CA 1`_ as :file:`ca-cert.pem`.
#. Place all three PEM files in the certificate folder (default: :file:`<app_src_dir>/certs/`).
   Ensure that the :kconfig:option:`CONFIG_MQTT_HELPER_PROVISION_CERTIFICATES` Kconfig option is set.
#. At runtime, the :ref:`lib_mqtt_helper` library loads the certificates and provisions them to the Mbed TLS stack.

.. note::
   Setting the :kconfig:option:`CONFIG_MQTT_HELPER_CERTIFICATES_FOLDER` Kconfig option is not required if the files are placed in the default :file:`certs` folder under the application source directory.

Key differences from nRF91
===========================

.. list-table::
   :header-rows: 1
   :widths: 40 30 30

   * - Aspect
     - nRF91
     - nRF70
   * - TLS stack
     - Modem hardware TLS
     - Mbed TLS (software)
   * - Credential storage
     - Modem secure storage (flash-backed)
     - Mbed TLS heap (runtime, from files)
   * - Provisioning tool
     - ``nrfcredstore``
     - None (file placement + Kconfig)
   * - CSR (on-device key gen) supported
     - Yes
     - No
   * - Private key exposed on host
     - No (CSR flow) / Yes (AWS keys flow)
     - Yes (always)
   * - Requires :ref:`at_client_sample`
     - Yes
     - No
   * - Max incoming TLS message size
     - ~2 kB (modem limitation)
     - Limited by available RAM
